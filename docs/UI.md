# UI 정렬 헌법 — 밴드·박스·구분선 규칙

"자유로우면서 정확하게": 테마는 크기를 자유롭게 정하되, 1px 어긋남은 구조적으로
불가능해야 한다. 이 규칙들은 vitest 게이트(`src/ui/cssContract.test.ts`)가 기계로
강제한다 — 기준을 통과 못 한다고 기준을 약화하는 것은 배신이다(기준 자체가 틀렸으면
문제 제기 후 정정).

## R1. 밴드 패딩 계약

수평 밴드(탭 스트립)의 상하 여백은 **스트립의 `padding-block` 변수만이 소유**하고,
항목(필·버튼·컨트롤)은 **stretch 로 안을 가득 채운다**:

- 뷰 탭 스트립: `--tab-pad` → `.view-tabs` (헤더 33 − 선 1 = 내부 32, 기본 4 → 칩 24)
- 워크스페이스 탭: `--ws-pad` → `.tabs`(타이틀바, 슬롯 36px)·`.content-tabs`
  (37px − 선 1 = 36) — 같은 변수 하나가 `.tab` ≡ `.ctab` 높이를 보장 (기본 5 → 26)

항목 높이 = 밴드 내부 − 패딩×2 가 **유도값**이므로:
- 형제 박스는 정의상 같은 높이·같은 축 — 1px 어긋남 구조적 불가.
- 패딩이 정수면 항목 y 도 항상 정수 — **절반픽셀 센터링 불가**. (높이 변수
  모델은 스트립·항목 높이를 따로 정해 홀짝이 어긋나면 0.5px 에 얹혔다 — 그래서
  폐기. 예: 칩 28 을 내부 37 에 센터 → y=48.5, 상하가 다르게 안티앨리어싱.)

테마(`data-tab-shape`)는 `:root[...] { --ws-pad: 4px }` 처럼 **패딩 변수로만**
크기를 자유 설정한다. 항목 셀렉터의 `height:` 지정은 **금지**(auto 제외) —
게이트가 빌드 실패시킨다. 예외는 가로 밴드가 아닌 곳뿐: `.project-rail`(정사각
칩), `.content-tabs.vertical`(세로 리스트).

**홀짝 규칙**: 밴드 내부 높이는 **짝수**로 잡는다(타이틀바 45−선1=44, 크롬 행
37−선1=36, 그룹 헤더 33−선1=32). 칩(짝수 패딩 차감 후)도 짝수가 되고, 칩 안의
짝수 콘텐츠(아이콘 12/14/16, 닫기 박스 16)까지 정수 센터링된다 — 모든 층위에서
절반픽셀이 사라진다.

## R1a. 크롬 행 계약

수평으로 **이웃한 밴드들**(좌측 헤더 `.ft-header` · 컨텐츠 탭 `.content-tabs` ·
우측 헤더 `.plugin-side-head` · 좌측 호스트 탭 `.left-host-tabs`)은 한 행이다 —
높이가 1px 만 달라도 구분선이 어긋난다. 높이는 파일 끝의 **규칙 하나**
(`--chrome-row-h`, 37px)만이 소유한다. 개별 블록에 height 지정 금지.

## R2. 정렬은 flex 가 소유

밴드는 `display:flex; align-items:center` 로 자식을 중앙 정렬한다. 위치 보정
(absolute + 음수 오프셋, margin 산수, translateY 미세조정)으로 "맞춰 보이게"
만드는 것은 금지. (이력: `.tab-close` 의 `top:-7px; scale(0.6)` 배지 핵 제거)

## R3. 구분선은 경계이지 여백이 아니다

밴드의 구분선은 `border`(레이아웃 점유)로 긋는다. 시각 대칭의 기준은
"위 여백 = 선 위까지의 아래 여백"이며, border 모델이 이를 자연스럽게 만족한다.
밴드 높이 산식: `패딩 + 항목 + 패딩 + 선(1px)` — 모든 항이 정수다
(예: `.content-tabs` 37 = 5 + 26 + 5 + 1).

## R3a. 테마는 변수이지 CSS 가 아니다

테마가 임의 CSS/SCSS 를 덮어쓰게 하지 않는다: 임의 CSS 는 R1 의 구조 보증을
테마마다 다시 무너뜨리고, 앱 구조
리팩토링 때마다 모든 외부 테마가 조용히 깨진다(전방 호환 붕괴). 테마의 표현
자유는 **승인된 변수 슬롯**(색 토큰 + 구조 노브: `--tab-pad`/`--ws-pad`/radius
류)으로 제공한다 — 노브가 부족하면 슬롯을 추가하는 것이 정도(正道)다.

## R4. 좌표 산수는 CSS 단일 규칙이 소유

JSX 에서 `calc(...)` 문자열을 조립해 인라인으로 흩뿌리는 것 금지. 위치가 필요한
레이어(GroupArea 셀/슬롯/프레임)는 **변수 4개(--l/--t/--w/--h)** 만 넘기고,
산수는 App.css 의 규칙 하나가 가진다. 치수 상수(--header-h/--status-h/--pane-inset)
는 TS 단일 소스에서 1회 주입.

위치 지정이 정당한 경우는 명시된 사유가 있을 때뿐이다:
영속 본문 슬롯(세션 보존), 분할 디바이더(경계 그 자체), 드롭 인디케이터(오버레이).

## R5. 정렬 주장은 수치로 검증한다

"맞아 보인다"는 근거가 아니다. `sok ui.measure '{"selector":".view-tab"}'` 로
rect 를 찍어 형제 박스의 y/h 일치와 여백 대칭을 숫자로 확인한 뒤에만 완료를
선언한다. (요소가 DOM 에 없으면 count:0 — 예: 레일 모드에서 `.tab` 부재는 정상)
