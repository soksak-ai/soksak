# soksak i18n — 두 축 규칙 (사람 해소 / LLM 합성)

soksak 의 모든 텍스트는 **소비자가 사람인가 LLM 인가**로 갈린다. 이 경계가 i18n 규칙의 전부다.
이 파일이 규칙의 단일 진실이다. 코드·플러그인·스킬은 여기서 어긋나면 틀린 것이다.

근거: ultracode 전수감사(34 에이전트) + 웹 연구(Agent Skills/MCP 규약) + 코드 확인(registry.ts:85–103, api.ts:741–757, spec.ts:242). pin 사고(한국어 발화 "브라우저에 표시했다" 발견 실패)가 LLM-facing 규칙의 출발점.

---

## 1. 두 축

| 표면 | 소비자 | 언어 정책 | 저장 형태 |
|---|---|---|---|
| 화면 UI(버튼·placeholder·라벨·툴팁·뷰 title) | 사람 | conversation_language 로 **해소** | `LocalizedText {en,ko}` / `t()` 키 |
| plugin.json `name`/`description`/command `title` | 사람(설치·동의·팔레트) | conversation_language 로 **해소** | `LocalizedText {en,ko}` |
| danger 게이트·동의 모달 메시지 | 사람 | conversation_language 로 **해소** | `{en,ko}` / `t()` |
| command/param `description`(CLI·MCP·skill 발견) | **LLM** | **전 언어 합성 단일 문자열** | base(en) + `triggers {en,ko,ja,…}` → 합성 |
| skill frontmatter `description` | **LLM** | **전 언어 합성 단일 문자열** | base(en) + 전 언어 트리거어 합성 |
| skill 도메인지도(명령 이름) | LLM | 영어 자동(식별자) — 손대지 않음 | — |

**한 줄 요약:** 사람용 = i18n 해소(한 언어로). LLM 발화/발견용 = **합성**(영어 base + 전 지원 언어 트리거어를 한 문자열로 생성). 언어가 늘면 합성이 자동 확장 — 기존 description 을 손대지 않는다.

---

## 2. 사람 표면 — 해소(resolve)

- 저장 = `LocalizedText`(spec.ts:242 `string | { en, ko }`). 단일 문자열은 단일 언어로 본다.
- 렌더 = `localize(text)`(i18n.ts) 또는 `t(key)`(i18n.ts 키 테이블, ko/en 완비)로 conversation_language 한 언어를 뽑는다.
- 화면노출 문자열을 소스에 평문으로 박지 마라. 전부 `{en,ko}` 또는 t() 키로 외부화.
- 뷰 title 을 한국어 평문으로 state 에 저장하지 마라(sessions.ts:358/374 안티패턴 — 언어 전환이 안 닿는다). i18n 키 참조로 전환.

---

## 3. LLM 표면 — 합성(compose), 해소 금지

### 3.1 왜 합성인가

1. **발화 매칭** — 사용자 대화 언어는 변한다. 한국어 대화에서 영어 단독 description 은 발화 매칭이 약하다(pin 사고). 그 언어 트리거어를 **더하면** 매칭 표면이 순증한다(영어 신호를 지우는 게 아니다).
2. **MCP 는 로케일 협상 채널이 없다**(`tools/list` 파라미터=cursor 뿐, 서버가 클라 언어를 모름). 로케일별 사본은 불가 — 정답은 **한 문자열에 전 언어 트리거어를 다 담는 것**. 단일 합성이라 MCP 한계를 우회한다.
3. **확장성** — 일본어·중국어 등이 늘어도 **합성이 자동 포함**해야 한다. 손으로 병합한 문자열은 언어 추가 시 전 description 을 다시 써야 하므로 금지. 언어는 **데이터**로 추가하고 합성이 흡수한다.
4. **비용은 작다** — 발견은 `sok help <cmd>` / `soksak_help` **온디맨드**다. 전 카탈로그를 한 번에 안 싣는다. 트리거어는 단어 몇 개(산문 아님)라 길이 영향 작음.

### 3.2 합성 아키텍처 (저작 ≠ 노출)

description 은 **둘로 저작**하고 시스템이 **합성**한다:

```
저작:  base(영어 역할·무엇·언제·왜)  +  triggers: { en:[…], ko:[…], ja:[…] }   (언어별 트리거 단어)
노출:  base + " | " + 전 언어 triggers 평탄화   ← catalogJson()/skill 생성 시점에 합성
```

- `base` = 영어 한 줄(역할·동작·언제·왜). LLM 정렬 골격.
- `triggers` = `LocalizedText` 형(언어→트리거어). 사용자가 그 언어로 칠 실어휘(예 ko: "낙서, 그리기, 표시, 주석", ja: "落書き, 描く").
- 노출 description = `base` 뒤에 **전 지원 언어** triggers 를 합성(언어중립 순서, 구분기호). MCP·skill·CLI 가 이 합성본을 본다.
- **언어 추가 = 각 명령 triggers 에 그 언어 키 추가**(데이터 1줄). base 와 다른 언어는 안 건드림. 합성이 자동 확장.

레지스트리 스키마에 `triggers?: LocalizedText` 필드를 추가(현재 없음 — Stage 1 도입). 없으면 base 만 노출(하위호환).

### 3.3 작성 표준 (셋 다 충족)

1. **stub 금지** — `description: name`(이름 복붙) 금지. base 는 "무엇 + 언제 + 왜". (pin·sakura·shark·claude-gui 가 어긴 사례 — `reg = (n) => register(n, { description: n })`. reg 헬퍼는 base·triggers 를 명시 인자로 받게 고친다.)
2. **합성** — base(en) + triggers(전 언어). 노출 예(pin.toggle):
   `Toggle screen doodle/annotation overlay — draw pen lines/text/circles over app·view·browser. Use when user marks or asks to draw on screen. | 낙서 그리기 표시 주석 화면에 그렸다 | 落書き 描く 注釈`
3. **담백·tight** — base 는 산문 아닌 한 줄, triggers 는 단어 나열(문장 아님). 비대화 금지(progressive-discovery 예산).

### 3.4 로케일 사본 금지

`description.ko` / `description.en` 같은 **완성 description 의 언어별 사본**을 만들지 마라(스킬·MCP 스키마에 없고, 언어 추가 시 N배 사본 폭증). 대신 base 1개 + triggers 데이터 → 합성 단일 문자열. 사람 title 은 `{en,ko}`(해소), LLM description 은 합성 string — 별개 소스다.

## 5. 스킬 분리와 i18n

- skill 분리 = **하이브리드, 숫자 아니라 균일 규칙**(범용 제어 스킬(환경별 `soksak(-dev|-debug)`) 1 + 도메인 전용 N). **어떤 플러그인도 안 숨겨짐** — 전 플러그인의 전 명령이 합성 카탈로그(`sok commands`)에 다국어 노출(발견의 본류). 스킬은 셸 가진 에이전트용 **부가** 계층.
- **메타데이터가 선언한다 — 코어는 목록을 들지 않는다**: 전용 스킬 필요는 **플러그인 `plugin.json` `contributes.skill`**(SKILL.md 경로)이 선언한다. 선언의 존재 = "나는 per-command 로 못 가르치는 시스템 절차지식이 있다"는 자기기술. `sok skill install` 은 활성 플러그인을 훑어 `contributes.skill` 보유분을 **균일 설치**한다. 코어 어디에도 `["erd","kanban"]` 류 하드코딩 목록 금지(`contributes.commands`/`views`/`nodes` 와 같은 매니페스트 선언 패턴). **확장**: 새 플러그인이 자격을 갖추면 자기 매니페스트에 한 줄 선언 → 코어 수정 0.
- **균일 게이트(선언 기준)**: 스킬의 고유 가치 = 본문 절차지식(도메인이 시스템으로 어떻게 작동=HOW). 트리거·WHAT 은 합성 카탈로그+control frontmatter 가 책임. 절차지식 없으면 선언하지 마라(스킬 본문=카탈로그 복붙=단일진실 위반 + frontmatter 상시 로드 비용). 첫 선언자(현재) = **erd**(관계 PK/FK측·.mig·3-dialect)·**kanban**(아웃라이너 트리=들여쓰기는 reparent·6뷰가 한 트리 투영)·**runbook**(Reference 링킹 그래프·순환검출·5실행타입·스케줄러). 미선언 = clip·mailbox·lgtv·claude-gui·dom-picker·acp-* (operation-collection) + sakura·shark·icons (trivial). 특수 케이스 아님 — 규칙의 현재 적용 결과.
- ERD 스킬은 `~/.claude/skills`(사용자 레벨, repo 분리) → erd 플러그인 repo 로 이전 + `contributes.skill` 선언(단일진실 교정).
- 전용 스킬 frontmatter description 도 §3 합성 규칙 적용(영어 base + 전 언어 트리거어).
- 스킬·언어가 늘어도 새 다국어 사본은 안 생긴다 — 도메인지도는 명령 이름(언어중립), description 은 base+triggers 합성 단일 문자열.

## 6. 검증 명제

언어 ko↔en 전환 시:
- **사람 UI 는 바뀐다**(버튼·title·동의 메시지). 안 바뀌면 i18n 누락(버그).
- **LLM description 은 안 바뀐다**(전 언어 합성이라 언어 독립). conversation_language 로 description 을 렌더하면 그게 버그 — MCP 에 로케일 채널이 없어 일관성·정렬을 잃는다.
- **새 언어(ja 등) 추가 시**: triggers 에 그 언어 키만 추가하면 합성 description 에 그 언어 트리거어가 나타난다. base·다른 언어·기존 description 은 불변.

e2e 소켓 하니스(SOKSAK_SOCKET)로 위 명제를 단언한다.

1. 코어 파이프라인 — `CommandSpec.triggers?: Record<string,string>` + 순수 `composeTriggers(base, triggers)` + `catalogJson()` 합성. skill frontmatter·MCP 메타툴 soksak-first 신호. **[구현 완료]**
2. 코어 카탈로그 ~249 — base 영어화 + triggers(ko) + 뷰 title state→i18n 키.
3. 플러그인 27 일괄 — plugin.json `{en,ko}` + stub 3(claude-gui·sakura·shark) reg 헬퍼 base/triggers + rich 10 + UI 문자열 외부화.
4. 스킬 — 플러그인-동봉 메커니즘(`contributes.skill`) + erd(repo 이전)·kanban·runbook 동봉 + frontmatter 합성.
5. 발화 E2E — should-trigger/should-not 시나리오(ko/en/ja) + Tier1(합성 description 트리거어 단언) + Tier2(실모델).

## 8. Rust 쪽 사람 표면

프론트가 뜨기 전이나 밖에서 Rust 가 사람에게 내보내는 문장이 있다 — 부팅 복구 OS 알림, VERSION_SKEW 봉투 message, `sok` stderr 판정. 이것도 §2 사람 표면이다. 해소하라. 프론트 키 테이블(`src/i18n.ts`)은 Rust 에서 닿지 못하므로 Rust 발원 사람 표면은 Rust 가 따로 소유한다.

- **로케일 단일 소스 = app.data kv(ns `core`, key `settings`, 필드 `language`).** 프론트가 언어 설정을 여기 영속한다(coreSync). Rust 는 이 한 곳만 읽는다 — 별도 로케일 저장을 새로 만들지 마라.
- **조회는 메시지 생성 시점 1회.** 폴링 금지. 소켓 연결당 1회(스큐 문장) 또는 알림 지을 때 1회(부팅 복구) 조회한다.
- **부재·판독 실패 = ko.** 프론트 기본값과 일치. 설정이 없거나(빈 DB·부팅 극초기) DB 판독이 실패하면 Korean 으로 해소한다.
- **`sok` CLI 는 앱 무관 단독 도구다 — 셸 로케일(LC_ALL 우선, 없으면 LANG)로 해소한다.** `ko*`→ko, 그 외·부재→en. 사람이 sok 을 치는 터미널의 로케일이 그가 읽을 언어다(앱 언어 설정과 독립).
- **문장 골격의 단일 소스 = `soksak-spec-socket`.** `skew_sentence` 가 두 언어 골격을 한 곳에 두고 `Lang` 으로 해소한다. 명사·해결 지시는 caller 가 해소해 넘긴다 — 전송 지시는 프로토콜 계약이 아니라 caller 소관이라 크레이트에 담지 않는다.
- **Rust 발원 사람 표면 소유 = `src-tauri/src/i18n.rs`.** 언어 조회 헬퍼(`app_language`)와 Rust 발원 문장(복구 고지)이 여기 산다. `Lang::from_tag` 는 태그 해석의 단일 지점(`soksak-spec-socket`).
- **LLM 발화·로그·식별자는 이 축을 지나지 않는다 — 영어.** `eprintln!` 개발 로그, capabilities, 명령 이름은 해소하지 않는다.

검증: 설정 `language=en` 인데 한국어 문장이 나오면(또는 그 반대) 버그다. 각 표면은 순수 함수(`recovery_body`·`hello_summary`·`skew_sentence`)로 분리해 언어별 단언으로 고정한다.

결정 완료(이전 미확정 4건):
