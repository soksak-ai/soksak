# Split-pane 레이아웃 규칙

상태: 적용 중

제품 layout 코드는 라이브러리의 상태·geometry 계약을 직접 사용한다. `SplitPane`에 `SplitPaneState`를 전달해 card rect와 divider를 받고 구조 변경은 라이브러리 메서드를 호출한다. React는 해당 rect 주변의 pane chrome과 plugin view 내용을 소유한다.

이 문서는 레이아웃 구현의 기준이다. 기존 코드의 동작이나 저장 포맷은 이 규칙보다 우선하지 않는다.
구현이 이 기준을 만족하지 못하면 기준을 낮추지 않고 구현·fixture·문서를 고친다. 기준 자체가 잘못되었다고
판단되면 먼저 이 문서를 정정하고, 정정된 기준으로 RED→GREEN을 다시 시작한다.

## 1. 소유권

- 레이아웃의 canonical 상태는 `split-pane`의 `SplitPaneState` 하나다.
- 콘텐츠 pane, 왼쪽/오른쪽 sidebar, rail은 모두 `CardInit` 카드다. 역할에 따른 별도 레이아웃 타입은 없다.
- rect, divider, rule, hit-test는 `SplitPane`의 공개 API에서만 얻는다.
- React 컴포넌트와 명령은 grid의 내부 배열, DOM 구조, 로딩 순서를 읽지 않는다.

### 1.1 저장소 경계

- 코어, 플러그인, 사이드카, 킷, 스펙, 계약, 라이브러리는 별도 구성요소다.
- `environment.json`은 설치된 구성요소와 버전을 기록한다. 배선을 정의하지 않는다.
- 구성요소 관계는 매니페스트의 `runtimeDependencies`로 선언한다.
- 구성요소 간 교환은 선언된 와이어 계약과 노출된 command, DOM, status 인터페이스로 제한한다.
- 코어 테스트는 경계의 fake와 fixture를 사용한다. 다른 구성요소의 소스, 경로, SDK, 빌드, 구현 이름을 검사하지 않는다.
- 구성요소는 자기 저장소에서 자기 구현을 테스트한다. 공통 사례는 계약이 정의하고 계약 구현 구성요소가 실행한다.

## 2. 좌표와 경계

- `xs`와 `ys`의 원소가 유일한 경계다. 같은 경계는 같은 배열 인덱스를 읽는다.
- 좌표를 비교해 같은 선이라고 판정하지 않는다. epsilon, snap-healing, 사후 equalize는 금지한다.
- rect는 `rects()`의 한 번의 계산 결과만 사용한다. 카드별 별도 좌표 계산은 금지한다.
- 카드가 차지한 span을 다른 카드가 가로지를 수 없다. 배치는 slicing 상태만 허용한다.
- gap은 카드 역할과 무관한 plane 규칙이다.

## 3. 연산

- split은 카드 하나를 둘로 바꾸며, 새 카드의 id와 payload를 명시한다.
- close는 마지막 카드가 아니면 성공해야 한다. 이웃이 공간을 메우거나 해당 slot을 제거한다.
- move는 close와 split을 호출자가 조합하지 않는 하나의 원자 연산이다.
- rail은 카드를 쪼개 만들어내지 않고 `insertAt`/`moveTo`로 전체 plane을 가로지르는 카드로 관리한다.
- px 크기와 fixed 여부는 카드 속성이다. 다른 카드 종류를 위한 별도 resize 규칙을 만들지 않는다.
- 연산 실패는 상태를 일부만 바꾸지 않고 원자적으로 원래 상태를 유지한다.

## 4. 영속성

- 저장·복원 단위는 `SplitPaneState`다.
- 복원 시 별도 정규화·치유·legacy 변환을 하지 않는다. 유효하지 않은 상태는 즉시 거부하고 원인을 보고한다.
- 내부 split id, tree node id, 렌더러용 임시 id는 저장 계약에 포함하지 않는다.

## 5. 검증 게이트

각 구조 변경 직후 다음을 검사한다.

1. 모든 rect가 유한하고 면적이 양수다.
2. 모든 카드 rect의 합집합이 plane을 정확히 덮는다.
3. 카드 간 겹침이 없다.
4. 인접 카드 사이의 gap이 plane 규칙과 일치한다.
5. 상태가 slicing이다.
6. 마지막 하나를 제외한 모든 카드가 `canClose`다.
7. fixed 카드의 크기와 span은 layout 연산으로 변하지 않는다.

검증 실패는 화면에서 숨기거나 다음 연산으로 넘기지 않는다. 해당 연산은 실패하고 구조화된 오류를 반환한다.

## 5.1 관측

- `layout.verify`는 선언 사각형과 실측 사각형 및 수치 차이를 반환한다.
- `ui.measure`는 노출 주소의 DOM 사각형을 반환한다.
- `window.snapshot`은 창 포커스를 변경하지 않고 픽셀을 캡처한다.
- `window.record`는 창 포커스와 애니메이션 상태를 변경하지 않고 유한 프레임을 기록한다.
- 캡처와 녹화는 관측 수단이다. 이미지 자체로 pass/fail을 판정하지 않는다.
- 애니메이션과 합성 검증은 프레임 기록과 위치 차이 수치로 pass/fail을 판정한다.
- 완료는 이벤트 알림으로 결정한다. 폴링과 타이머 기반 완료 판정은 주 수단으로 사용하지 않는다.
- 테스트 산출물은 저장소의 테스트 또는 command 계약으로 관리한다. 추적되지 않는 임시 스크립트와 임시 테스트 폴더는 검증 절차에 포함하지 않는다.
- symlink를 사용하지 않는다. 경로는 선언된 설정 또는 발견된 인터페이스로 해석한다.

## 6. 완료 기준

완료된 구현은 하나의 layout 상태 계약과 직접적인 `SplitPane` 연산을 사용하며, tree 변환,
fallback layout, 좌표 보정 경로를 포함하지 않는다.
