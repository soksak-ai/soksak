# 증거

시각적 주장을 어떻게 판정하는가.

## E1. 판정하는 것은 숫자이지 그림이 아니다

"보기에 맞다" 는 증거가 아니고 "보기에 틀렸다" 도 증거가 아닙니다. 캡처는 무슨 일이 있었는지 보여주고,
판정은 숫자를 반환하는 명령에서 나옵니다.

2026-08-15 실측: pane 오른쪽에 외곽선이 없는 문제를 오후 내내 스크린샷으로 논쟁했습니다. `ui.measure`
가 위아래 테두리만 답했기 때문입니다. 네 변을 모두 답하게 하자 원인이 한 번의 읽기로 드러났습니다 —
web view 가 자기 창보다 1 포인트 커서 문서의 마지막 열이 창 밖에 있었습니다. "그렸는데 안 보임" 과
"안 그림" 은 그림에서는 같아 보이지만 서로 다른 결함입니다.

## E2. 명령이 먼저다

숫자를 만드는 명령이 없으면 그것을 씁니다. 수치 판정자가 없는 시각 축은 판단의 문제가 아니라 끝나지
않은 작업입니다.

## E3. 캡처는 포커스를 가져가지 않는다

캡처는 이 프로세스 자신의 창 내용을 쓰므로 화면 녹화 권한이 필요 없고, 창을 올리거나 포커스하지
않으며, 창이 가려져 있어도 동작합니다. 포커스를 빼앗는 캡처는 자기가 측정하는 대상을 바꿉니다.

## E3a. 사람이 보고 있으므로 애플리케이션은 계속 실행한다

E3 은 캡처가 포커스를 가져가지 않게 합니다. 같은 이유가 그 이상을 금지합니다. 화면의 창은 누군가의
작업 환경이며, 관측이 관측 대상을 방해해서는 안 됩니다.

애플리케이션 종료가 그 방해의 가장 큰 형태이고, 2026-08-16 에 약 열다섯 번 있었습니다 — 재빌드 전마다,
`go tool wails3 task verify` 전마다, 그리고 확인 후 닫힌 채로 두었습니다. 세 이유 중 둘은 틀렸습니다.
플러그인 변경에는 재시작이 아니라 `plugin.reload` 가 필요하고, `verify` 가 남은 인스턴스와 충돌하는
일은 드물어서 미리 막기보다 생겼을 때 처리하면 됩니다.

재시작이 필요한 것은 코어 재빌드입니다. 실행 중인 프로세스가 옛 이미지를 보유하기 때문입니다. 따라서
그때는 재시작하고, **확인이 끝나면 다시 시작합니다.** 닫힌 채로 두지 않습니다.

## E4. 증거를 두는 곳

workspace 의 `evidence/` 아래, 애플리케이션 저장소 밖입니다. 생성된 이미지가 소스 파일이 되지 않게
하기 위함입니다. 게이트 실행마다 디렉터리 하나입니다.

## E5. 프레임 번호가 공유 시계다

`window.record` 는 PNG 를 다 쓸 때마다 프레임 번호를 0 부터 보고합니다. 모든 저널 항목이 그 번호를
포함하므로, 저장된 픽셀과 기록된 측정이 같은 순간을 가리킵니다. 두 순간에 읽은 두 값은 화면에 있은 적
없는 프레임을 만듭니다.

## E6. 대상과 출처를 공유하는 계측기는 실패할 수 없다

읽기는 대상에 대해 답합니다. 대상이 만들어진 것과 같은 기록에서 조립한 읽기는 대상이 무엇을 하든 그
기록에 동의하며, 바로 그 읽기가 잡으려던 경우에 성공을 보고합니다.

2026-08-16 실측, 하루에 셋:

- **캡처가 원장에서 그렸습니다.** 각 표면에 자기 픽셀을 요청해 인벤토리가 주장한 사각형에 그렸으므로,
  잘못된 창에 붙은 브라우저가 올바른 창의 그림에 나타나고 사람이 보고 있던 pane 은 비어 있었습니다.
  제거함: ScreenCaptureKit 캡처는 이미 모든 네이티브 자식을 담으므로(NATIVE-LAYER), 계측기는 창을
  읽고 아무것도 그리지 않습니다. 게이트: `frameworks/wails/capture_read_test.go`.
- **`surface.composition` 이 모든 창에 대해 인벤토리 하나를 답했습니다.** 창 둘, 답 하나, 편차 0,
  그런데 브라우저가 있는 것은 그중 하나뿐이었습니다. 모든 읽기를 그 대상 창에 키로 묶고, 컴포지터가
  선언에서 되풀이하는 대신 네이티브 객체에서 읽어 표면이 실제로 놓인 창을 보고하도록 고쳤습니다.
- **재시작 digest 가 이름 변경을 보지 못했습니다.** `state.fingerprint` 는 id 를 담지 않는데, 그것이
  판정하는 형태에는 맞습니다. 그래서 복원 시 모든 id 를 바꾼 변경이 그 게이트를 통과하면서 터미널
  재부착 키를 깨뜨렸습니다. 이제 게이트가 digest 옆에서 이름들도 단언합니다.

따라서 **관측 표면은 대상을 읽고, 읽을 수 없는 곳에서는 어떤 주장을 하지 않는지 말합니다.**
`surface.composition` 은 네이티브 객체에서 `misparented` 를 이름 짓고, 캡처 노트는 무엇을 그리지
않았는지 이름 지으며, `window.monitors` 는 presence 를 답하면서 사각형이 사람 앞에 있는지는 답하지
않는다고 GATES.md 에 밝혀 둡니다.

## E7. 게이트는 결함에 대해 한 번, 무는 것을 증명한다

AGENTS 3-1 은 수정 전에 RED 를 요구합니다. 이미 올바른 동작 위에 쓴 게이트는 보여줄 RED 가 없고,
실패할 수 없는 게이트는 없는 것보다 못합니다 — 안전하다고 보고하기 때문입니다.

그래서 의도적으로 결함에 대해 실행합니다. 옛 동작을 되돌려 놓고, 게이트가 이름과 함께 실패하는 것을
확인하고, 다시 되돌립니다. 2026-08-16 실측, 네 번 — 재구성된 라벨 조립이 `lib/viewPark.ts:101` 에서
보고됨, 형식은 유효한 카운터가 스트림 재적재 단언을 `expected 'stm-aaaabb' not to be 'stm-aaaabb'` 로
실패, 옛 방식으로 키를 만든 projection seed 가 workspace 루트에 `undefined` 를 답함, 재발급 복원이
pane id 가 안정적이어야 하는 자리에서 `pan-ufetu2` 를 답함.

probe 는 같은 자리에서 제거합니다. 남겨진 probe 는 아무도 선택하지 않은 결함입니다.
