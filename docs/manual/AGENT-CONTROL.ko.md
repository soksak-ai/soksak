# 에이전트 제어

에이전트가 이 애플리케이션을 구동하는 방법과, 어느 표면이 무엇에 답하는지.

## A1. registry 가 유일한 출처

명령 표가 무엇이 존재하는지, schema 가 무엇인지, 위험 등급이 무엇인지, 어떻게 실행되는지를 정합니다.
어떤 채널도 자기 목록을 갖지 않습니다. CLI help, MCP 도구, 스킬 자료, 문서는 모두 그 표에서
도출되며, 어느 것도 사본이 아닙니다.

## A2. 전송은 담고, 교재는 가르친다

`sok` 과 MCP 서버는 전송입니다. registry 를 호출하고 결과를 되돌립니다. 교재는 에이전트에게 명령을
어떻게 발견하는지 알려주며 명령 목록을 담지 않습니다 — 교재의 목록은 플러그인이 무언가를 등록하는 첫
순간에 틀립니다.

## A3. 주입보다 발견

채널은 모든 명령을 한 번에 노출하는 대신 발견을 노출합니다 — 목록, 그다음 schema, 그다음 실행. 메타
도구 셋(`commands`, `help`, `run`)이 명령 수가 늘어도 도구 수를 고정된 채로 유지합니다.

## A4. 권한 검사는 registry 에 하나

위험 검사는 registry 와 함께 정의되며 원격 호출자(CLI, MCP, 소켓)에 적용됩니다. UI 에서 조작하는
사람은 원격 호출자가 아닙니다. 어떤 채널도 그 검사를 다시 구현하지 않으며, 플러그인의 명령도 같은
검사를 지납니다.

## A5. 채널은 얇다

채널 핸들러는 `state.commands` 를 호출하고 요청을 전달합니다. 검증, 라우팅, 검사, 식별자 대조는
registry 의 몫입니다. 두꺼운 채널은 채널마다 자기 버그를 하나씩 만듭니다.

## A6. 환경은 바이너리의 identity 다

바이너리의 설치본은 빌드할 때 고정됩니다. 그것을 바꾸는 `--env` 플래그도 환경변수도 없습니다. 그런
스위치는 명령이 조용히 잘못된 설치본에 도달하는 경로입니다. 그 위의 유일한 권위는 `SOKSAK_SOCKET`
이며, 애플리케이션이 자기가 소유한 터미널에 주입합니다. 그 설치본이 실행 중이 아니면 답은 다른
설치본으로의 대체가 아니라 오류입니다.

## A7. 이벤트는 명령과 대칭이다

코어는 명령 표면과 같은 모양의 구독 표면을 소유하므로 아무것도 폴링하지 않습니다. 연결이 곧 구독이며,
그 수명이 스트림의 수명입니다. 항목에는 단조 증가 sequence 가 있어 누락된 항목이 공백으로 드러나고,
클라이언트는 추측 대신 커서로 재연결합니다.

장기 연결이 없는 클라이언트는 대신 `activity.recent {since}` 를 읽습니다. 요청 시점의 따라잡기 읽기는
폴링이 아닙니다.

## A8. 실행된 모든 것은 보인다

registry 명령, 터미널 명령, 에이전트 turn 이 모두 기록되고 UI 는 그 기록의 view 입니다. 두 출처가
공급합니다. 플러그인 이벤트, 그리고 `registry.execute()` 안의 계측 — 명령 이름, 출처(ui 또는 remote),
위험 등급, 소요 시간, 표준 응답 envelope.

민감한 값(`pass`, `token`, `secret`, `auth` 등)은 가립니다. 답은 보여주고 비밀은 보여주지 않습니다.
비밀을 보호하려고 답 전체를 숨기면 이 기능이 존재하는 이유인 관측이 사라집니다.

## A9. 전송 중립

로컬 창과 원격 클라이언트가 같은 스트림과 같은 명령 표면을 소비합니다. 위험 검사는 전송이 아니라
호출자의 출처를 기준으로 합니다. 코어에는 특정 원격을 위한 코드가 없습니다.

## A10. 개발용 MCP 는 검사가 아니다

Wails 는 빌드 태그 뒤에 MCP 서버를 포함하며, 문서가 그것을 실험적이라고 표시합니다. 개발 중 보고
클릭하는 데 유용합니다. 판정은 이 애플리케이션 자신의 표면 — control plane 과 테스트 스위트 — 에서
나옵니다. MCP 서버는 프로덕션 빌드에 존재하지 않기 때문입니다.
